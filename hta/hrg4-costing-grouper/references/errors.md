# Errors and validation

The grouper validates mandatory input fields during grouping. Where one or more fields fail, it
derives `UZ01Z Data Invalid for Grouping` in place of a real HRG. Validation continues after the
first failure, so the quality file reports everything wrong with a record together - which makes
it worth reading the full error list per record before concluding what the problem is.

All values are validated against the design database. ICD-10 and OPCS-4 codes not on the list are
invalid but produce no specific error category:

```
DIAG_XX|XXXX|Diagnosis is invalid
OPER_XX|XXXX|Procedure is invalid
```

## Cascade rules

- **Upward within APC.** Any episode with `UZ01Z` forces the spell HRG to `UZ01Z`. An unbundled
  HRG of `UZ01Z` forces the episode, and therefore the spell core HRG, to `UZ01Z`.
- **Never downward.** A `UZ01Z` episode HRG does not overwrite the episode's unbundled HRGs.
- **Critical care exception.** `XA*` (neonatal), `XB*` (paediatric) and `XC*` (adult) unbundled
  HRGs are generated by the separate critical care modules and flow outside the admitted patient
  care commissioning data set, so they cannot influence the core APC HRGs.
- Best Practice Tariff codes are suppressed when a spell HRG is `UZ01Z` (payment groupers only).

The practical consequence for reconciliation: spell-level `UZ01Z` rates are always at least as
high as episode-level rates, and a single bad episode can invalidate a long, otherwise clean spell.
When quantifying data quality, report both.

## Error message format

Three sections separated by pipes:

```
Code Type|Code|Error Message
```

`Code Type` names the field or field type. `Code` is the unrecognised value, left blank where the
error is an absent value. The message describes the failure. Example:

```
DIAG_01|P102|UZ03 - Diagnosis Conflicts with Age
```

## Error types

**Field validation errors** - a value is missing or outside the accepted range:

```
DIAG_01||Primary Diagnosis is blank
DIAG_01|R69X6|UZ01 - Invalid Primary Diagnosis
OPER_02|C992|Procedure is invalid
```

**Spell validation errors** - cross-record consistency checks within a spell:

```
SEX||Sex is inconsistent in spell
STARTAGE||Age rises by more than expected in the spell
```

These almost always indicate a spell identifier problem rather than a coding problem: if
`PROVSPNO` is not unique within provider, unrelated patients are merged into one spell and their
sex and age immediately conflict.

**Clinical coding errors** - codes that breach coding conventions or are too unspecific to
indicate resource use. These carry the error category codes below.

## Error categories

| Code | Name | Meaning | Example |
|---|---|---|---|
| UZ01 | Invalid Primary Diagnosis | Valid code, but conventions forbid it in the `DIAG_01` position | `DIAG_01|Z509|UZ01` - Z509 care involving use of rehabilitation procedure, unspecified |
| UZ02 | Poorly Coded Primary Diagnosis | Permitted as a primary diagnosis but too vague to indicate resource use | `DIAG_01|T140|UZ02` - T140 superficial injury of unspecified body region |
| UZ03 | Diagnosis Conflicts with Age | A paediatric primary diagnosis on a patient aged 19 or over | `DIAG_01|P704|UZ03` - P704 other neonatal hypoglycaemia |
| UZ04 | Diagnosis Conflicts with Anatomical Site | Invalid combination of primary diagnosis and site; applies only to certain musculoskeletal codes with a 5th digit | `DIAG_01|M7217|UZ04` - M7217 knuckle pads, ankle and foot |

### Repairing stripped leading zeros

Padding restores a known width; it does not restore destroyed information. Whether a damaged file
can be repaired depends on the code structure, which for A&E codes is now verified - see
`references/em_codes.md` for the full national code tables and the derivation.

| Damaged value | Field | Reading | Repairable |
|---|---|---|---|
| `6` | `INV_*` | `06` only - the national component is always 2 digits with no national sub-analysis | Yes, deterministically |
| `6` | `TREAT_*` | `06` only - `00` is not a valid treatment code, so `006` never existed | Yes |
| `11` | `TREAT_*` | `11` (incision and drainage) **or** `011` (dressing, minor wound) | **No** |
| `13` | `TREAT_*` | `13` only - `013` would need sub-analysis 3 on Dressing, which has only 1-2 | Yes |
| `011` | `TREAT_*` | as-is; the zero survived | Yes - not damaged |

Exactly ten 2-character treatment values are irrecoverably ambiguous: **11, 12, 31, 32, 33, 41, 42,
43, 51, 52**. Each is both a valid 2-digit code and a valid stripping of a sub-analysed
`0A` + digit combination. The grouper flags none of them, because both readings validate - so a
blanket-padded file runs clean and mis-costs those attendances silently. Re-extract from source with
the column typed as text; do not repair by inference.

Everything else is recoverable, because the structure is positional: treatments are a 2-digit code
optionally followed by one sub-analysis digit, investigations are 2 digits flat.

One quick diagnostic: if any value in a column still carries a leading zero, that column probably
was not numerically coerced, because the conversion is column-wide. Mixed evidence points at a
different root cause. `diagnose_stripped_zeros()` in `scripts/write_grouper_input.R` reports both
signals per field.

An error naming a value that is itself a valid national code is not a leading-zero problem. Check
for a local sub-analysis suffix being submitted (it should not be), an RDF column offset, or a
grouper-year mismatch.

## Triage recipe

Work from patterns down to records, not the other way round. Read `[name]_quality_rel.csv`, count
by `Code Type` and `Error Message`, and match the shape of the result against the causes below.

| Pattern | Usual cause |
|---|---|
| A large block of `TREAT_*` or `INV_*` failures across EM records | Leading zeros stripped, typically by an Excel round trip |
| `RENALMOD` / `RENALSITE` failures across most NRD records | Same - leading zeros |
| `SEX is inconsistent in spell`, or age rising implausibly | Spell identifier not unique within provider; unrelated episodes merged |
| Every record failing on the same field | RDF column position wrong - the field is reading the neighbouring column |
| Every record failing, many fields at once | Header row present but `-h` omitted, or an RDF/dataset mismatch |
| Far fewer records processed than submitted | Input truncated - often trailing empty fields lost on an Excel save |
| Scattered `UZ01`/`UZ02` primary diagnosis errors | Genuine clinical coding issues; feed back to coding rather than patching data |
| Scattered `UZ05`/`UZ06` procedure errors | Genuine - the code cannot drive grouping. The record still needs costing by another route |
| `Procedure is invalid` / `Diagnosis is invalid` in bulk | Codes retired since the activity was recorded, i.e. a mismatch between the grouper's ICD-10/OPCS-4 version and the data's - common when grouping older years with a current grouper (see `multi_year_grouping.md`) - or codes carrying suffixes the grouper does not expect |

Two habits worth keeping. First, quantify before fixing: the proportion of records affected tells
you whether this is a pipeline defect (usually a large, uniform block) or genuine data quality
(usually scattered). Second, decide and document how `UZ01Z` records are handled downstream -
excluded from unit cost calculation, or costed by a fallback method - because that choice affects
results and reviewers will ask.
